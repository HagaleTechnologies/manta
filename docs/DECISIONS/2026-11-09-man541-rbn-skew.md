# MAN-541: an RBN skew reading in ppm, a `/healthz` warning and a shipped alert

Date: 2026-11-09
Status: implemented.

MAN-301's `[rbn_compare]` already measured each band's median frequency
offset from the RBN (`manta_rbn_compare_freq_offset_median_hz{band}`), and
`docs/RUNBOOKS/rbn-comparison.md` told the operator to convert it to ppm by
hand. RBN-OPS judges nodes partly on skew (SM7IUN's rbnskew), so an
automatic reading is admission evidence. This record holds the decisions
behind the reading, the warning and the alert. The code is
`crates/manta-server/src/rbn_compare/skew.rs`, the `rbn_skew_*` methods of
`Metrics` and `status_doc.rs`'s `rbn_compare` object.

The ticket's third scenario, `manta calibrate --from-rbn --write`, is not in
this change: it moved to a follow-up ticket to keep the change reviewable.
Until it lands, the operator copies the `SET` value `manta status` prints
into `freq_correction_ppm`. D8 and D14 record what the follow-up builds.

## Decisions

### D1: the key is `freq_correction_ppm`

The value lives in `freq_correction_ppm` in `[input]` or an `[[input]]`
entry. The ticket's `[input] ppm` does not exist.

### D2: two numbers, named apart

*Skew* is per band: the median of each spot's
`(manta − RBN modal) / RBN modal × 10⁶`. Positive means manta reads high,
the direction of a CW Skimmer `FreqCalibration` above 1.

The *suggested `freq_correction_ppm`* is per config entry:
`round_ppm(((1 + a·10⁻⁶) / (1 + o·10⁻⁶) − 1) · 10⁶)`, where `a` is the value
the daemon applies and `o` is the entry's pooled skew. The sign is
MAN-127's: a receiver reading high gets a negative correction. The value
replaces the old one. The offsets are measured after the applied
correction (`calibration_factor_from_ppm` scales the reported frequency),
so the ticket's `−offset` reading leaves a residual equal to `a`:

```text
error +3.00 ppm, applied +0.00: observed +3.000 ppm; naive -observed = -3.000 -> residual -0.000; (1+a)/(1+o)-1 = -3.000 -> residual +0.0000
error +3.00 ppm, applied -2.00: observed +1.000 ppm; naive -observed = -1.000 -> residual +2.000; (1+a)/(1+o)-1 = -3.000 -> residual -0.0000
error -1.50 ppm, applied +1.00: observed -0.500 ppm; naive -observed = +0.500 -> residual -1.000; (1+a)/(1+o)-1 = +1.500 -> residual +0.0000
```

`skew::tests::the_suggestion_replaces_rather_than_adds` pins the three rows.

### D3: per-spot ppm uses RBN's modal frequency

Each grade's offset is divided by its `rbn_modal_freq_hz`, not a band
centre. This agrees with `offset_hz / band_centre_hz × 1e6` to first order
and is exact on wide bands. The offset ring keeps the modal frequency.

### D4: precision is `50 Hz / √n / f_med`

50 Hz is half of RBN's 100 Hz resolution (`grade::RBN_RESOLUTION_HZ`), and
`f_med` is the band's median modal frequency. A Monte Carlo model
(stations spread over a 30 kHz segment, RBN's modal rounded to 100 Hz,
5 Hz of manta noise) matched the closed form within 10%: 20m with n=20 gave
0.80 by formula against 0.73 simulated, and 40m with n=60 gave 0.92 against
0.89.

### D5: a band reading needs 20 spots

`MIN_SKEW_SAMPLES = 20`, the ticket's number. Under it a band shows its Hz
median and `needs 20 spots`, with no ppm.

### D6: the warning rule

A band is over when it has at least 20 spots, `skew_warn_ppm > 0`, its
`ppm_error ≤ skew_warn_ppm / 3`, and `|skew| > skew_warn_ppm`. It warns once
it has been over without a break for 30 minutes (`SKEW_HOLD`), evaluated on
the comparator's 5 s tick. Any failed condition, or the band's spots ageing
out, clears it.

The `/3` guard is tighter than the research's `/2`. Simulated 24 h days
with a 60-minute ring and the 30-minute hold gave a perfectly calibrated
node near the guard boundary a warning on 14.7% of days (80m, 220 spots/h)
and 8.0% (40m, 70 spots/h) with `/2`, against 0.0% for both with `/3`. 20m at
25 spots/h still caught a +3 ppm error on 95% of days. At the default of
2 ppm, a band warns only at about 1680 spots/h on 160m, 447 on 80m, 114 on
40m, 55 on 30m, 29 on 20m and 20 from 17m up. A ppm error is common to
every band, so the higher bands carry the warning, as rbnskew skips bands
below 7 MHz.

### D7: suggestions are per config entry, warnings per band

Spots are attributed to inputs by track id: input `i` of `n` owns tracks
`1+i, 1+i+n, …` (MAN-13 D3, as `HearingCounters::record` does). An entry's
streams are pooled: a band plan's streams share one receiver and one
`freq_correction_ppm`. The pooled skew is the inverse-variance weighted
mean of the entry's band medians over bands with at least 20 of its spots,
with error `1/√Σw`. The ring stores raw track ids and attributes at read
time, so grades recorded before the daemon registers its inputs are
attributed too. Band rows and the warning stay node-wide per band, like
the existing Hz gauge.

### D8: a save needs ±1.00 ppm

A suggestion is fit to save only when the pooled error is at most
`MAX_SAVE_ERROR_PPM = 1.0`; `manta status` marks a coarser one `too coarse
to save`. Otherwise 20 spots on 80m (±3.2 ppm) would be saved as a
correction. The follow-up's `calibrate --from-rbn` refuses below the same
line.

### D9: `/healthz` stays a liveness probe

The first line, the 200/503 status and `manta_healthy` are unchanged.
`WARN rbn skew <band>: …` lines follow the check lines. A 503 would make
orchestrators restart a node whose only fault is a drifted oscillator,
MAN-128 D10's argument for keeping the RBN uplink out of the verdict.
`manta health` reads line 1 only, so it prints the line and exits 0.

### D10: `/status` gains one additive object

`rbn_compare` is omitted when comparison is off, and `schema_version`
stays 1.

### D11: `manta status` prints the block before the uplink section

`render_human` returns early when no uplink is configured, so the block
goes first. A node without `[rbn_compare]` prints exactly what it printed
before. The exit code stays uplink-only.

### D12: one new key, `[rbn_compare].skew_warn_ppm`

Default 2.0 (rbnskew's good-citizen line); 0 turns the warning off;
validated as a number from 0 to 1000 (`manta_spot::MAX_ABS_PPM`);
restart-only like every `[rbn_compare]` key. The other numbers are code
constants: 20 spots, 30 minutes, `/3` and ±1.00.

### D13: the alert fires on the daemon's state

`MantaRbnSkew` fires on `manta_rbn_compare_skew_warning == 1` and reports
`manta_rbn_compare_freq_offset_median_ppm`. A node's own `skew_warn_ppm`
cannot live in a static shipped rule, and the daemon already holds 30
minutes, so the rule has no `for`. promtool 3.5.0 passed `check rules` and
`test rules` on it during planning; CI does not install promtool, so
`monitoring_kit.rs`'s structural tests are the enforced check.

### D14: `--from-rbn` opens no receiver (follow-up)

The follow-up's `calibrate --from-rbn` reads the daemon's `/status` through `daemon_client::run_status`, picks
the entry, and hands the suggestion to the WWV path's save tail
(`offer_save`, `save`, `config_edit::save_freq_correction_ppm`): the same
prompt, `--write`, already-set line, atomic replace, environment warning
and saved line. A daemon whose receiver a command-line source flag chose
already reports `replaced_by_flag` in this change (`manta status` notes it
as `source set by a flag`), and the follow-up's `--write` refuses it.

### D15: no "bands disagree" refusal

Per-entry attribution removes the blended-oscillator case that motivated
one, the precision weights discount noisy bands, and the band rows show any
disagreement.

### D16: determinism and wire bytes

`[rbn_compare]` is refused on a replayed recording, so decoder output and
spot logs cannot change. The `track_id` added to `GradeInput` and
`SpotGrade` is `#[serde(skip)]`, so `spotGrade` JSON and `manta grade`
output stay byte-identical. The existing `_median_hz` and `_samples` lines
are unchanged.
