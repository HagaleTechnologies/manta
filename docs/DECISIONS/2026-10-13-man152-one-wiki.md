# MAN-152: the in-repo wiki is canonical; disabling GitHub's Wiki is pending

## Decision

`wiki/` in this repository is manta's only wiki. README, `docs/README.md`
and CLAUDE.md already send readers to [`wiki/INDEX.md`](../../wiki/INDEX.md),
and the wiki is reviewed and versioned with the code it describes. The
wiki points at the code and `docs/` and loses any conflict with them.

GitHub's built-in Wiki tab is not used. Disabling it remains an owner
step. GitHub can turn the tab on or off; it cannot redirect it, so
disabling it will satisfy "the other is disabled or redirects". The
native wiki has never had a page (`git ls-remote
https://github.com/HagaleTechnologies/manta.wiki.git` answered
`remote: Repository not found.` on 2026-10-13).

The owner turns the feature off with:

```text
gh api -X PATCH repos/HagaleTechnologies/manta -f has_wiki=false
```

(or Settings → General → Features → clear **Wikis**). After that change,
confirm it with this query, whose expected output is `false`:

```text
$ gh api repos/HagaleTechnologies/manta --jq .has_wiki
false
```

On 2026-10-13 that query returned `true`. This change did not run the
PATCH. The implementing session's GitHub token was scoped to the
`MAN-152` branch and its pull request, and changing a repository setting
is owner-gated here, as release settings are
([MAN-244](2026-10-10-man244-release-governance.md)). The owner must run the
command above separately. Auto-merge does not change this setting;
Scenario 2 remains pending until the owner confirms `has_wiki: false`.

The wiki's metadata is refreshed and pinned in CI:

- All 17 pages in `wiki/pages/` were re-verified against `d286147` and
  stamped `verified: {commit: d286147, date: 2026-10-13}`. Six were still
  stamped 2026-07-07 and one 2026-07-24. Two had no frontmatter at all.
  Several stamps predated decision records that their own pages cited.
- The re-verification fixed the claims that were no longer true: four
  `docs/SPEC-decode-core.md` anchors that never resolved, PR #154
  described as unmerged, the metrics listener's pre-MAN-132 `0.0.0.0`
  bind, a `manta-dsp::centroid` module that does not exist, a per-vector
  coppa pin that lives in `Cargo.toml`/`Cargo.lock`, and an
  unimplemented streaming Watterson API.
- `wiki/manifest.json` lists all 17 pages, not 10, with fresh hashes.
  `wiki/wiki.toml` says `visibility = "public"`, which matches the
  repository; the manifest copies that value into its root and every entry.
  The root also preserves `schema: wiki-manifest/v1` and `repo: manta`.
- `wiki_manifest_lists_every_page_with_a_matching_hash` in
  `crates/manta-cli/tests/docs_consistency.rs` fails when the manifest and
  the pages drift apart. It checks that every page has an entry, that
  each entry's hash is the SHA-256 of its page body after the closing
  frontmatter delimiter (CRLF normalised to LF), matching the existing
  `wiki-manifest/v1` generator,
  and that the entry's `id`, `title`, `kind`, `status`, `maintainer`,
  `locked`, `sources`, `links` and `verified_commit`/`verified_date` match
  the page's frontmatter. A page edit must regenerate its manifest entry in
  the same change.

## Why the in-repo wiki, not GitHub's

- **Reviewed with the code.** A `wiki/` edit goes through a pull request
  and CI. A GitHub wiki edit goes through neither, and the
  `docs_consistency` tests cannot see it.
- **Versioned with the code.** A page's `verified.commit` names a commit
  in this repository. A GitHub wiki lives in a separate git repository
  with no link to the code's history.
- **Already the one in use.** CLAUDE.md's knowledge-wiki section, the
  `/wiki-update` workflow and `docs/README.md` all name `wiki/INDEX.md`.
  The native wiki is empty.

## Scope

- Scenario 1 of MAN-152, that `wiki/pages/overview.md` no longer calls
  manta "design-phase" with "no implementation started", was already true
  on `main`: the page reads "Implementation is well underway", and
  `wiki_overview_verified_stamp_is_not_the_pre_rewrite_one` pins it. This
  change did not edit the overview's body. The page was re-verified and
  re-stamped with the rest.
- Other GitHub features (Discussions, Projects, Issues) are unchanged.
- No manta code path or decoder output changes.
- The manifest was regenerated once for this change. There is no
  committed generator. `/wiki-update` remains the workflow that maintains
  it, and the test above keeps its output honest.
